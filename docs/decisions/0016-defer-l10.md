# 0016: Defer live check L10 and close iteration 2 testing

- **Status:** Accepted
- **Date:** 2026-11-08
- **Amends:** iteration 2 testing in [test-plan.md](../test-plan.md)

## Context

L10 checks FR-16's kept case live: Delete on a background session whose worktree has uncommitted, untracked, and ignored files should show Kept with the FR-16 message, and the files should survive (U-10).

`claude --bg` refuses to start in a git repository until someone accepts its trust prompt, and a git repository doesn't inherit trust from a trusted parent folder. This project's own repository counted as untrusted for background sessions too. Agents don't accept trust prompts, because doing so changes a Claude Code security setting on the owner's PC.

## Options considered

- **The owner trusts a throwaway repository:** about a minute of the owner's time, then an agent runs L10 and deletes the repository.
- **Release without L10:** record it as not run and list the gap in the release notes.
- **Defer L10 to a later iteration's testing:** keep it as a known open check.

## Decision

Defer L10 to a later iteration's testing. The owner chose this after first choosing to trust a throwaway repository and then asking Claude to accept the prompt itself, which it declined to do.

## Consequences

- FR-16's kept case is covered by unit tests and code review only.
  - The tool never passes `claude rm`'s forcing flags (C-8), so Claude Code's own check decides whether a session is kept.
  - What isn't checked live is the CLI's real exit code and "kept" wording on Windows, and the page's handling of that real result.
- If the CLI's wording changes, a kept session shows as Failed rather than Kept. The design accepts that, because it errs on the safe side.
- The release notes must say that L10 wasn't run.
- L10 stays in the test plan for the next iteration.

## Closing Testing

The owner was then asked whether to close iteration 2 Testing with two more limits, and chose "Yes, close Testing":

- **NFR-8:** the buttons and dialogs pass the automated accessibility and keyboard tests but haven't been checked with a screen reader. Decision 0013 now applies to NFR-8 as it does to NFR-5, so the project makes no screen-reader claim for them.
- **FR-11:** a real notification was delivered and clicked with the dashboard tab visible. Delivery to a hidden tab couldn't be simulated, so it's unverified.

The release notes must list both.
