# Requirements

- **Status:** Iteration 1 tested on 2026-11-06. Iteration 2 requirements signed off on 2026-11-06.
- **Scope:** Iteration 1 is live monitoring. Iteration 2 adds desktop notifications and session control. Windows first.

## Functional requirements

| ID    | Requirement                              | Acceptance criteria                                                                                                                                                                                                                                                                                                                                                           |
| ----- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-1  | List active sessions                     | Running interactive and background sessions from `claude agents --json` appear on the dashboard.                                                                                                                                                                                                                                                                              |
| FR-2  | Keep recently finished sessions          | Finished sessions the tool observed while running, and completed background sessions reported by the CLI, stay listed for 24 hours and are marked as finished. A background session the CLI no longer lists, such as after `claude rm`, leaves the dashboard straight away. Interactive sessions that end while the tool is off aren't listed, and the docs state this limit. |
| FR-3  | Show identity and status                 | Each session shows its name, project folder, kind (interactive or background), and current status. The name comes from the CLI, which can use prompt text until a title is generated, and it isn't stored, so a finished session the CLI no longer lists shows as unnamed after a restart.                                                                                    |
| FR-4  | Show time information                    | Each session shows its start time and how long it has been running.                                                                                                                                                                                                                                                                                                           |
| FR-5  | Show why a session needs the user        | Sessions needing attention show the reason when the CLI provides it, or a generic "needs input" label otherwise.                                                                                                                                                                                                                                                              |
| FR-6  | Show latest activity metadata            | Each session shows its git branch, model, and last activity time when available. A branch reported as `HEAD` counts as unavailable. If no timestamp can be read from a transcript, last activity is the file's modified time. A missing value doesn't hide the session or cause an error.                                                                                     |
| FR-7  | Highlight sessions needing attention     | These sessions are listed first with a clear marker that doesn't rely on color alone. Stale sessions, as defined in [0009](decisions/0009-dashboard-ui.md), appear in a separate collapsed group.                                                                                                                                                                             |
| FR-8  | Show an attention count                  | The browser tab title shows how many sessions need attention, excluding stale sessions.                                                                                                                                                                                                                                                                                       |
| FR-9  | Stay current                             | Session changes appear on the dashboard within 5 seconds.                                                                                                                                                                                                                                                                                                                     |
| FR-10 | Announce new attention to screen readers | A session that newly needs the user is announced politely, with its name and reason. Sessions already waiting when the page opens are not announced.                                                                                                                                                                                                                          |

## Constraints

| ID  | Constraint                                                                                                                                                                                                                                    | Source                                                  |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| C-1 | The tool itself must not change Claude Code settings or files under `~/.claude`. It changes sessions only through FR-14 to FR-17, at the user's request: through the CLI, which can also remove a worktree, or by ending a process for FR-17. | [0014](decisions/0014-iteration-2-scope.md)             |
| C-2 | The tool must never read, log, or display `~/.claude/.credentials.json` or session `.key` files.                                                                                                                                              | [0002](decisions/0002-product-direction.md)             |
| C-3 | The tool must not depend on `~/.claude/jobs/<id>/`.                                                                                                                                                                                           | [0002](decisions/0002-product-direction.md)             |
| C-4 | Transcript reads must not store or display message text.                                                                                                                                                                                      | [0006](decisions/0006-transcript-metadata.md)           |
| C-5 | Iteration 1 doesn't use hooks.                                                                                                                                                                                                                | Requirements review, 2026-11-06                         |
| C-6 | Windows is supported first, and the code stays portable.                                                                                                                                                                                      | [0003](decisions/0003-first-iteration-and-platforms.md) |
| C-7 | The store must not contain session names, because they can hold prompt text.                                                                                                                                                                  | [0011](decisions/0011-testing-bug-fixes.md)             |

## Out of scope for iteration 1

- Starting, stopping, resuming, or otherwise controlling sessions
- Sending prompts or answering permission requests
- History, search, cost, and token analytics
- Message previews
- Desktop or browser notifications
- macOS and Linux support

## Non-functional requirements

| ID    | Requirement                | Acceptance criteria                                                                                                                                                                                                                                                                              |
| ----- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| NFR-1 | Local access only          | The server listens only on the loopback interface and is unreachable from other devices.                                                                                                                                                                                                         |
| NFR-2 | Token required             | Requests without the valid random token are rejected. The token isn't written to logs.                                                                                                                                                                                                           |
| NFR-3 | No data leaves the machine | No telemetry or error reports are sent. The running tool makes no external network requests, and the dashboard loads all its assets locally.                                                                                                                                                     |
| NFR-4 | Degrade on change          | When Claude Code output changes or data is missing, the dashboard keeps showing what still works, marks what is missing, and displays a clear banner. A missing `status` on an identified interactive session not listed in the previous successful poll doesn't raise the banner for that poll. |
| NFR-5 | Accessibility              | The dashboard is built towards WCAG 2.2 AA and passes automated axe scans and keyboard tests. It doesn't claim conformance, and hasn't been verified with a screen reader. See [0013](decisions/0013-release-without-wcag-claim.md).                                                             |

## Iteration 2

Decisions are in [0014](decisions/0014-iteration-2-scope.md).

### Functional requirements

| ID    | Requirement                               | Acceptance criteria                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| FR-11 | Offer desktop notifications               | The user turns notifications on from the dashboard, which triggers the browser's permission prompt. They arrive while the page is open, including in the background. If permission is denied or unavailable, the page says so and works as before.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| FR-12 | Notify about events                       | A notification is sent when a session newly needs the user or its specific reason changes, when a background session newly finishes, when a session newly fails, and when the tool can't read sessions. "Newly" compares against the last successful snapshot. The first successful snapshot only sets the starting point and sends nothing, and the comparison carries across reconnects. Stale sessions, interactive sessions that end, a reason falling back to the generic label, and changes caused by the user's own Stop, Delete, or End from the dashboard don't notify. A background session stopped outside the dashboard still notifies as a finish, because the tool can't tell who stopped it. A session that fails notifies as a failure only. Turning notifications on later doesn't send earlier events. |
| FR-13 | Keep notifications private and quiet      | A session notification shows the project folder name and the reason, and never the session name or message text. A failure to read sessions says only that. Each event notifies once across open tabs, events in the same snapshot are combined, and a failure to read sessions notifies once until it recovers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| FR-14 | Open or resume a session                  | From its row, a session with a short `id` opens in a new terminal through `claude attach`. A finished interactive session with a valid session ID opens through `claude --resume`. The terminal is Windows Terminal, or a standard console if that isn't available. A repeated click doesn't start a second terminal for the same session while a launch is in progress, and for a short period Design sets. A session with neither ID offers no Open.                                                                                                                                                                                                                                                                                                                                                                   |
| FR-15 | Stop a background session                 | From its row, after confirmation, the tool runs `claude stop`, for the states Design identifies as stoppable. The dialog says work in progress is interrupted and the conversation is kept.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| FR-16 | Delete a background session               | From its row, after confirmation, the tool runs plain `claude rm`. The dialog says the session is removed and any work it's doing stops, and that a worktree Claude created is removed when that's safe. Success is confirmed from the next listing. If the CLI keeps the session, the page says so in the tool's own words and says work may need saving or another session closing first. It never shows or runs a forcing command, and it doesn't point to agent view's delete, which can discard uncommitted changes.                                                                                                                                                                                                                                                                                                |
| FR-17 | End an interactive session                | Offered only for a listed interactive session with a process ID. After confirmation, the tool checks that the process ID still belongs to the session, immediately before each signal, and refuses if it can't confirm that. It requests a normal close, waits for the time Design sets, and offers a Force end with a second confirmation if the session is still listed. If Design finds no reliable normal close, the action is a confirmed Force end. Dialogs say work in progress can be lost.                                                                                                                                                                                                                                                                                                                      |
| FR-18 | Report action results                     | The page shows whether each action succeeded or failed, in the tool's own words, never raw command output. If the outcome can't be confirmed, such as a timeout or a failed poll, the page says it's unknown. For Open, success means the terminal launched. The list reflects the change within the FR-9 limit.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| FR-19 | Name the target clearly                   | Every dialog identifies the session by name when it has one, and otherwise by project folder, kind, and start time.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| FR-20 | Help find a live interactive session      | A live interactive session has no Open action. Its row shows its project folder and process ID, so the user can find its terminal.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| FR-21 | Act on a notification click               | Clicking a notification brings up the dashboard tab, as far as the browser allows, and highlights the session's row. A combined notification highlights every row it covers that's still listed. A read failure, or a session that has gone, highlights nothing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| FR-22 | Protect the session that started the tool | Stop, Delete, and End aren't offered for a session that started the tool.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

### Constraints

| ID   | Constraint                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Source                                      |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| C-8  | The tool never passes `claude rm`'s `--discard-unpushed` or `--force-remove-worktree` flags.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | [0014](decisions/0014-iteration-2-scope.md) |
| C-9  | Stop, Delete, and End act only on sessions in a current successful listing. They and Resume are blocked while the latest poll has failed or the listing is older than the limit Design sets. Resume may take the session ID from the store, but the current listing must confirm that session isn't live. Open by short `id` isn't blocked, because it's non-destructive, uses a validated ID from the server's own data, and stays useful during a CLI outage. The server rechecks the session's kind, state or status, and process ID when it runs the action. | [0014](decisions/0014-iteration-2-scope.md) |
| C-10 | Iteration 2 doesn't use hooks and doesn't send prompts or answer permission requests.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | [0014](decisions/0014-iteration-2-scope.md) |
| C-11 | `claude` and `wt` must resolve ahead of launch to locations outside the session's folder, and never through a search of it, so a program planted there can't run. Tests use a fake CLI and a planted file with `NoDefaultCurrentDirectoryInExePath` removed from the environment, because that setting can make the test pass falsely, and run against the installed launcher type.                                                                                                                                                                              | [0014](decisions/0014-iteration-2-scope.md) |

### Non-functional requirements

| ID     | Requirement                             | Acceptance criteria                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------ | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NFR-6  | Actions can't be triggered from outside | Actions need a valid session cookie, a matching `Host`, and a matching `Origin`. A missing `Origin` is rejected. Reads and page loads can't trigger them, and the page can't be framed.                                                                                                                                                                                                                                       |
| NFR-7  | The page can't choose what runs         | The page names an action and a session. The server builds a fixed command from its own data. IDs must pass a strict format check before use. A folder path is passed as a process option, never in command text. Tests cover hostile folder names and IDs, including `&`, `%`, `^`, and `;`.                                                                                                                                  |
| NFR-8  | Keyboard and accessibility              | Actions and dialogs work with the keyboard. Focus moves into a dialog and returns to its row or the next sensible element. They pass the automated accessibility checks.                                                                                                                                                                                                                                                      |
| NFR-9  | Security review                         | A review of the action routes finds no open Critical or High issue before release.                                                                                                                                                                                                                                                                                                                                            |
| NFR-10 | Actions are enforced by the server      | Only one action runs per session at a time, and none retries automatically. CLI calls have a timeout, with a defined result if one expires. The server accepts Force end only after a normal close of the same session and process ID, or when Design has found no reliable normal close. The server refuses Stop, Delete, and End for a session that started the tool. Confirmation dialogs alone don't count as protection. |

### Out of scope for iteration 2

- Answering prompts, sending messages, and hooks
- History, search, cost, and token analytics
- Native Windows notifications, and notifications with the page closed
- Jumping to a live interactive session's existing terminal
- Forcing a delete that the CLI refused
- Starting new sessions, and renaming or forking sessions
- macOS and Linux terminal handling
