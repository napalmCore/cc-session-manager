# Requirements

- **Status:** Iterations 1 and 2 released as 0.1.0. Iteration 3 requirements signed off on 2026-11-09, by agent review and merge (0019). Iteration 3 released as 0.2.0. Iteration 4 requirements signed off on 2026-11-13, by agent review and merge (0024).
- **Scope:** Iteration 1 is live monitoring. Iteration 2 adds desktop notifications and session control. Iteration 3 adds token use and estimated cost, ends leftover programs, and fixes open bugs. Iteration 4 adds starting and forking sessions, a history of past sessions, and search inside conversations. Windows first.

## Functional requirements

It requests a normal close, waits for the time Design sets, and offers a Force end with a second confirmation if the session is still listed. Dialogs say work in progress can be lost.                                                                                                                                                                                                                                                                                                                      |

| FR-21 | Act on a notification click               | Clicking a notification brings up the dashboard tab, as far as the browser allows, and highlights the session's row. A read failure, or a session that has gone, highlights nothing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| FR-22 | Protect the session that started the tool | Stop, Delete, and End aren't offered for a session that started the tool.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

## Iteration 4

Decisions are in [0023](decisions/0023-iteration-4-plan.md) and [0024](decisions/0024-iteration-4-requirements.md). Iteration 4 is planned for release as 0.3.0.

### Functional requirements

| ID    | Requirement                     | Acceptance criteria                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-32 | Start a session                 | A "New session" form takes a folder, a kind, an optional name, and, for a background session, a prompt. The folder can be any existing local folder, typed or picked (NFR-14). A background session starts as `claude --bg` with the prompt. An interactive one opens in a new terminal, as Open does. A name is passed with `--name=<name>`. Pressing Start is the confirmation, and the button is disabled until the result arrives. Nothing is retried automatically. A background start succeeds when Claude Code reports it started, and the session appears in the list within FR-9's 5 seconds. An interactive start succeeds when its terminal launches, as for Open (FR-18), because the session may wait at Claude Code's own trust prompt. A refusal, such as an untrusted folder, is shown in the tool's own words (FR-18). |
| FR-33 | Fork a session                  | Any session with a session ID can be forked: running, finished, or from History, including the session that started the tool (FR-22 doesn't apply, because the original is never changed). The Fork form takes a kind, an optional name, and, for a background fork, a prompt. The server takes the session ID and folder from its own data, never from the page, and runs `claude --resume <session ID> --fork-session` in the session's folder, with `--bg` for a background fork. `--fork-session` is always passed, so the original session is never continued or changed. Fork isn't offered, and is refused, when the folder no longer exists. Pressing Fork is the confirmation. Results follow FR-32's rules for each kind (FR-18).                                                                                             |
| FR-34 | Name sessions only at start     | A name can be given when a session is started (FR-32) or forked (FR-33), through `--name=<name>`. Existing sessions can't be renamed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| FR-35 | Show a history of past sessions | A History view lists every session whose main transcript is still on disk under `~/.claude/projects`, newest last activity first, 50 at a time. Each shows its folder, branch, model, start time, last activity, token use, and estimated cost, by FR-23 and FR-24's rules, but no name (C-7). Each offers Resume (FR-14's rules) and Fork (FR-33). A session already in the main list is marked as such. The first page shows within 5 seconds of opening History, with later details filling in as they're read.                                                                                                                                                                                                                                                                                                                      |
| FR-36 | Search inside conversations     | A search box finds sessions whose prompts or Claude's visible replies contain the search text, case-insensitive and as plain text. It covers user and assistant message text in main transcripts only. It leaves out tool calls, tool results, subagents, Claude's thinking, and text Claude Code inserts as user messages, such as command output, compaction summaries, and reminders. Each result shows the number of matches, a snippet of at most 160 characters around each of up to three matches, and the session's folder and last activity, and offers Resume and Fork as History does (0026).                                                                                                                                                                                                                                |

### Constraints

| ID   | Constraint                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
